# Unilabs Supabase database

This directory contains the versioned database changes and regression tests for the Unilabs AI Appointment Demo.

## Applied migrations

- `20260818081423_appointment_platform_hardening.sql`
- `20260818081433_demo_scenario_automation.sql`

Both migrations are applied to Supabase project `mshxmttxwfkvexchwjkr`. The repository also contains a compressed Base64 copy of the larger first migration. Run `./materialize_migrations.sh` to reconstruct and checksum-verify the plain SQL file when required.

## Active demo scenario

The current baseline is generated by:

```sql
select public.reset_demo_scenario(
  (now() at time zone 'Europe/Amsterdam')::date + 1,
  7,
  5
);
```

This creates seven calendar days for Amsterdam, Rotterdam, and Utrecht, with nine hourly slots per location and day. The 12:00 slot remains non-bookable. The reset also restores the central Patient A/Patient B baseline, Patient C, Patient E, background capacity, and verified fictional chat/voice identities.

## Main RPCs

Channel-neutral read RPC:

- `check_availability`

Idempotent write RPC overloads requiring `request_id`:

- `book_appointment`
- `join_waitlist`
- `reschedule_appointment`
- `cancel_appointment`
- `decline_waitlist_offer`

Operational RPCs:

- `reset_demo_scenario`
- `expire_waitlist_offers`

Legacy overloads remain temporarily available so the existing Vercel endpoints continue to work until the integration layer is updated.

## Automated expiry

The `pg_cron` job `unilabs-expire-waitlist-offers` runs every minute and calls:

```sql
select public.expire_waitlist_offers();
```

## Tests

Every test executes in a transaction and ends with `rollback`:

- `tests/001_central_story.sql`
- `tests/002_unhappy_paths.sql`
- `tests/003_decline_and_expiry.sql`
- `tests/004_consistency.sql`

The migration was first executed with rollback validation. The same four suites were then rerun successfully after the migrations were applied.

## Reset

Run `reset.sql` to restore tomorrow as the active scenario date, seven generated days, and a five-minute waitlist-offer hold.

All patient and channel identity data is fictional demo data.
